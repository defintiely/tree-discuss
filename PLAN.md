# Tree Discuss — план разработки

Веб-приложение для ведения дискуссий деревом реплаев на 2D-канвасе.
Ответ создаётся от **выделенного фрагмента текста** в родительском узле, а не от узла целиком.

Сначала MVP — минимум, на котором штукой можно реально пользоваться.
Всё остальное лежит в §6 и ждёт, пока MVP не покажет, что из этого действительно нужно.

---

## 1. Суть

Канвас с деревом текстовых узлов. Ребро дерева привязано к конкретному диапазону символов
внутри текста родителя: «цитата → ответ», разложенная в 2D.

Единственное архитектурно нетривиальное место — **якорь на диапазон текста**
(`start`/`end` offset в тексте родителя). Всё остальное — обычный CRUD.

## 2. Стек

| Что | Чем | Почему |
|:---|:---|:---|
| Сборка | Vite + React + TypeScript | статическая сборка: `npm run dev` локально, `dist/` на любой хостинг |
| Канвас | React Flow (`@xyflow/react`) | пан/зум/drag/стрелки из коробки, ~80% работы по канвасу |
| Состояние | Zustand | маленькое, сериализуемое |
| Хранилище | IndexedDB (`idb-keyval`) | живое состояние в браузере, автосейв с дебаунсом |
| Обмен | CSV (`papaparse`) | формат экспорта/импорта: git-диффы, правка руками, Excel |
| Эмодзи | нативный пикер ОС (Win+.) | в вебе это просто юникод, рендерит системный шрифт |

Однопользовательский режим.

## 3. Модель данных

Дерево — плоская таблица через `id` + `parent_id`. Отдельной сущности «ребро» нет:
раз у узла ровно один родитель, вся информация о связи (кто родитель + какой фрагмент
процитирован) живёт в строке ребёнка. Рёбра для рендера — **производные**:

```ts
edges = nodes.filter(n => n.parent_id).map(n => ({ source: n.parent_id, target: n.id }))
```

### nodes.csv

```
id,parent_id,kind,title,text,x,y,anchor_start,anchor_end
n1,,root,Начало,"Основной тезис...",0,0,,
n2,n1,reply,Ответ,"Не согласен...",340,120,15,42
n3,n1,reply,Ответ,"А вот здесь...",340,400,88,151
n4,n2,conclusion,Вывод,"Значит...",680,120,0,20
```

| Колонка | Тип | Смысл |
|:---|:---|:---|
| `id` | string | уникальный id узла |
| `parent_id` | string \| пусто | родитель; пусто только у корня |
| `kind` | `root` \| `reply` \| `conclusion` | тип узла → цвет и иконка шапки |
| `title` | string | заголовок: Начало / Ответ / Вывод |
| `text` | string | тело узла, многострочное |
| `x`, `y` | number | позиция на канвасе |
| `anchor_start`, `anchor_end` | number \| пусто | диапазон в тексте **родителя**; пусто у корня |

### reactions.csv

Реакций на узле много, поэтому они — вторая таблица (одна строка на реакцию),
а не список внутри ячейки. Так ни в одной ячейке нет JSON.

```
node_id,emoji,count
n1,👍,3
n1,🤔,1
n2,🔥,2
```

## 4. MVP — декомпозиция по задачам

Оценки в рабочих часах, итого ≈ 20 ч ≈ 2,5 рабочих дня.

### Этап 1 — Скелет и хранилище (4 ч)

| # | Задача | Готово, когда |
|:---|:---|:---|
| 1.1 | `npm create vite` (react-ts), React Flow, Zustand, papaparse, idb-keyval | `npm run dev` открывает пустой канвас с паном и зумом |
| 1.2 | Типы `Node`, `Reaction`, стор Zustand: `Map<id, Node>` + селектор детей по `parent_id` | стор отдаёт корень и его детей |
| 1.3 | Рендер узла: шапка (иконка + заголовок), тело, тень; один корневой узел | корень виден, тащится мышью, `x`/`y` пишутся в стор |
| 1.4 | Автосейв в IndexedDB с дебаунсом 500 мс + загрузка при старте | перезагрузил страницу — узел на том же месте |
| 1.5 | Экспорт: кнопка → скачивает `nodes.csv` и `reactions.csv` | файлы открываются в Excel, колонки как в §3 |
| 1.6 | Импорт: выбор файлов → парсинг → замена состояния | экспорт → импорт того же файла даёт идентичное дерево |

**Проверка этапа:** создал дерево, выгрузил CSV, почистил IndexedDB, загрузил CSV — дерево вернулось целиком.

### Этап 2 — Якорь на выделение (10 ч) ⚠️ сердце проекта

| # | Задача | Готово, когда |
|:---|:---|:---|
| 2.1 | Текст узла рендерится сегментами: режем строку по границам всех якорей этого узла | узел без якорей — один сегмент; с двумя якорями — до пяти |
| 2.2 | Ловим `window.getSelection()`, пересчитываем в offset'ы относительно текста узла | выделил слово → верные `start`/`end` |
| 2.3 | Всплывающая кнопка «Ответить» у выделения | появляется у выделения, прячется по клику мимо |
| 2.4 | Создание дочернего узла: `parent_id`, `anchor_*`, позиция справа-вниз от родителя | новый узел с фокусом в поле ввода |
| 2.5 | Подсветка процитированных фрагментов рамкой — постоянная, не только при наведении | рамка видна после перезагрузки |
| 2.6 | Пересекающиеся якоря: сегменты сортируются, вложенная цитата рисуется поверх внешней | ответ на слово + ответ на предложение с этим словом — обе рамки читаемы |

**Проверка этапа:** три ответа на три фрагмента одного абзаца, один из них перекрывает другой;
три рамки видны, три ребра ведут куда надо, после перезагрузки всё на местах.

### Этап 3 — Рёбра и раскладка (4 ч)

| # | Задача | Готово, когда |
|:---|:---|:---|
| 3.1 | Производные рёбра из `parent_id`, стрелка на конце | дерево из 5 узлов рисуется связным |
| 3.2 | Кастомный edge: старт — от координаты `<span>` цитаты, а не от края узла | две стрелки из одного узла выходят из разных мест текста |
| 3.3 | Перерасчёт точки старта при драге и зуме | стрелка не отрывается при таскании |
| 3.4 | Автопозиция нового узла с обходом занятых мест | 10 ответов подряд не наложились друг на друга |

### Этап 4 — Ввод текста, реакции, типы узлов (4 ч)

| # | Задача | Готово, когда |
|:---|:---|:---|
| 4.1 | Двойной клик по телу — правка текста, Esc / клик мимо — сохранение | текст меняется и переживает перезагрузку |
| 4.2 | Пикер эмодзи на узле, клик по существующей реакции — ±1 | реакции переживают перезагрузку и экспорт |
| 4.3 | Переключатель `kind`: Начало / Ответ / Вывод → цвет и иконка шапки | «Вывод» визуально отличим, ведёт себя как обычный узел |
| 4.4 | Удаление узла: рекурсивно всё поддерево, с подтверждением «удалить 7 узлов?» | отказ ничего не трогает |

Удаление именно рекурсивное: перевесить детей на деда нельзя — их якоря указывают
в текст узла, которого больше нет.

### Этап 5 — Публикация (2 ч)

| # | Задача | Готово, когда |
|:---|:---|:---|
| 5.1 | `vite build` → GitHub Actions → GitHub Pages | открывается по публичной ссылке |
| 5.2 | README: локальный запуск, формат CSV | чужой человек запускает по README без вопросов |

## 5. Риски MVP

| Риск | Когда бьёт | Что делаем |
|:---|:---|:---|
| Пересекающиеся якоря | ответ на слово + ответ на предложение с ним | Этап 2.6: резка на сегменты закрывает by design; наивное «обернуть в span» — нет |
| Правка текста родителя сдвигает якоря | как только начнёшь переписывать уже отвеченный текст | в MVP осознанно не решаем: подсветка съедет, ребро останется. Лечится колонкой `anchor_quote` (§6) |
| Браузер не пишет в файл на диске сам | всегда | CSV — формат экспорта по кнопке, не формат хранения |
| Канвас тормозит на 200+ узлах | на большом дереве | до ~100 узлов не думать |

## 6. После MVP — очередь, а не обещания

Ничего из этого не делаем, пока MVP не покажет, что это нужно.

**Целостность якоря при правке текста**
- колонка `anchor_quote` — страховка: offset'ы уехали → позиция переищется по сохранённой цитате
- diff старого и нового текста → сдвиг offset'ов
- оторванный якорь: цитата не нашлась → пометка на ребре, ребро живо, подсветка гаснет
- экранирование `\n` в CSV, чтобы абзацы переживали правку файла в Excel

**Управление большим деревом**
- `closed` — закрыть тред: узел и поддерево приглушены
- `collapsed` — свернуть поддерево, на узле бейдж с числом скрытых
- фокус-режим: показать только ветку выбранного узла
- авто-раскладка «привести в порядок»
- миникарта

**Удобство**
- undo / redo
- поиск по тексту с перелётом камеры
- горячие клавиши
- редактируемый `title` (в MVP заголовок задаётся типом узла)
- валидация импорта: висячий `parent_id`, цикл, дубли `id`, ноль или >1 корня

**Шеринг**
- режим «только чтение» по ссылке с зашитым состоянием
- File System Access API: выбрал папку один раз — CSV пишется на диск молча (Chrome/Edge)

**Не входит вообще**
- совместное редактирование в реальном времени (нужен сервер + CRDT, +2 недели)
- аккаунты, авторство, права
- мобильная вёрстка
- картинки и вложения
